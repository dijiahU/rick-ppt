# Pinterest and authorized visual discovery

Use Pinterest when a finished poster, editorial layout, identity, photograph or
other visual work can answer the current page's design question. It is one
discovery source alongside original portfolios, museums and publications. Search
the subject plus the visual relationship you need, not only “beautiful PPT”.
For example, a music poster's type/image hierarchy is a useful question; the
example is not a required genre, query, style or reference count. Respect the
task's search permissions, faithful-edit scope and supplied-only requirements.

## Discover through the tools already available

- With hosted search (or `pptx_search_sources`), try a focused public query such
  as `site:pinterest.com/pin/ jazz poster typography`. Follow a useful Pin to its
  original designer/publication when accessible. Return the exact Pin URL,
  original-source URL, supported title/creator, and a direct image URL only if
  it was actually exposed by a tool. A saved board or search grid is a lead,
  not an inspected individual work. Broaden beyond Pinterest when that helps.
- In a local harness with an already exposed, authorized browser, search and
  open the actual work; use its image/screenshot channel to inspect the pixels.
  Preserve a task-local reference image when supported so the continuing author
  can see it too. A browser login or tool available in another session is not
  automatically available here. Check capabilities.json: when browser_research
  exposes pptx_browser_sources and authorized sites, that mediated route can use
  the operator-authorized Edge session. It does not expose cookies or arbitrary
  tabs. If absent, use hosted search and the media broker; do not assume login
  inheritance. Customer-funded/DSH tasks do not inherit the operator account.
- A login wall, empty result, blocked page or slow browser is a retrieval limit.
  Use an accessible original source/other reference or retain the limitation.
  Do not repeatedly reload, install a browser, copy cookies or switch accounts.
  Do not infer the cause of an “offline” banner from the banner alone.

For open research/new design, follow content.md's broad first pass: actually
attempt the currently advertised channels before narrowing, even if ordinary
search found a plausible reference. Tailor queries to each source and record real
outcomes in existing notes. A platform attempt does not require adopting its work;
blocked/unavailable channels remain limited, with no repeated retries or new access.

## Get actual pixels to the author

A Pin URL is a webpage, not an image. Use an observed public direct-file URL
(which may be on `i.pinimg.com`) through the existing task-local media broker,
with the Pin/original page as `--source-page` and the page/design question as
`--purpose`. Follow `WEB-MEDIA.md` when the host provides it. Do not guess an
`originals/` URL by rewriting a thumbnail URL, bypass access checks or download
whole boards. If this harness has no broker, use only its permitted acquisition
and image-viewing tools. No new service or credentials are implied.

Inspect the acquired picture through the actual image channel. Record whether
it is a thumbnail, CDN derivative, browser screenshot or verified original;
retain its observed dimensions and detail limits. A search response, prefetch
`ready`, downloaded file or Markdown image link alone is not visual inspection.
If the picture is too small for the needed detail, inspect a legitimately
available larger version or choose a different reference.

Reuse the existing `decision-plan.json` reference register: `id`, `kind`, `title`, `creator`,
`source`, `inspection`, `evidence`, `observed`, `borrowed`, and
`applications[].pages/action` (see workflow-branches.md for the full schema).
For an inspected local image, `inspection="local_image"` and `evidence` points
to that task-local file. Record Pin-only attribution and an unvisited original
source honestly in notes; a Pinterest account name is not proof of authorship.
Unavailable pictures stay unavailable, with no invented observations/application.

Before committing a dependent page composition, call the exposed
`pptx_page_design_context` for its stable page ID to receive applicable local
reference pixels. On CLI-only harnesses, run the existing page context command
and open those files with the image viewer. Reuse existing files/records across
pages; do not keep unrelated pictures in each page's input. If only a previous
browser view exists, that does not prove a separate author saw it.

Transfer a concrete relationship (scale, image/type integration, figure/ground,
color area or rhythm) into this page's own editable objects and inspect the
rendered effect. Keep inspiration and embedding rights separate: viewing a Pin
does not authorize embedding its artwork. No new layout rule, image quota,
research phase or review gate is required.
