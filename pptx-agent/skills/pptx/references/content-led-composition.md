# Content-led composition and pacing

Read during planning, sequential authoring, or a repair of repeated composition.
Use the existing strategy/form/composition/behavior branches; this is guidance
inside them, not another stage, decision schema or approval gate.

For the current page, resolve these linked decisions before creating objects:
1. The audience question and the specific evidence, example or operation answering it.
2. The concrete focus, relative scale, reading path, image/type relationship and
   entry→click groups→complete view that express this answer.
3. The editable objects, image files, connector endpoints and semantic groups
   implementing that composition. Tools implement it; tool defaults do not choose it.

Keep the existing role and visual_action concise and specific to the actual content.
Record essential units, assumptions and qualifiers alongside the content. Long
research detail belongs in source notes; sources, artwork transfer and optional
extensions can use slide notes. Essential self-reading meaning stays on the canvas.
This is not a mandatory per-page questionnaire or a text/image quota.

## Enclosures and visual hierarchy

Choose a visible enclosure when it communicates a boundary, independent entity,
state or comparison unit. Explain that meaning compactly in visual_action when
using repeated enclosures. A reusable filled rectangle containing a heading and
paragraph must not become the default implementation of every strategy.
Text can use hierarchy and deliberate placement without a box. A relation can use
aligned labels, a retained spine or actual object detail. Image and editable type
can overlap or share a field when the crop and contrast support the explanation.
These are operations inside the selected branches, not a prescribed page rotation.
Keep a shared encoding for genuinely comparable material; vary content-specific
focus, proportion and reading path when the communicative task changes.

A native semantic group is an editing/animation relationship, not a visible card.
Text, a detail annotation and a connector can enter together with no enclosing fill.
Use returned native handles for grouping, connecting and revealing. Do not repeatedly
parse XML for newly created object IDs or build a universal node() layout wrapper.
Reuse measurements, identifiers and chosen deck-wide typography/color roles;
choose position, geometry, enclosure, scale and emphasis for the current meaning.

For example, a general process explains order; a worked example must show its actual
input, judgment and changed output, rather than re-label the same process boxes.
A multi-agent explanation needs a traceable task/state/validation example when it
claims how collaboration works. Distinguish documented behavior from a labeled
illustrative scenario. An action page may prioritize a trial and its inspection
questions. These examples illustrate decisions, not required content for every deck.

## Reference application

Find a reference addressing the current dominant problem: composition and rhythm,
type hierarchy, spatial explanation, crop, or image/type integration. Product UI
and chart teaching may solve some pages without solving the body-page composition.
Inspect relevant work before settling that direction, within the permitted search
route. Any relevant art form is eligible. Stop searching when there is a usable
principle; implement and inspect it. Record exact work→observed property→borrowed
principle→concrete page action in the existing v3 register and final notes. A name
or palette claim is insufficient. Do not require outside artwork when supplied
style, offline constraints or a simple task makes it inappropriate. Record an
honest design basis instead of fabricated influence. No reference count or RAG.

## Sequence and efficient verification

Author in order. At a natural section/milestone, compare already completed page
previews as a contact sequence, reusing their images. Check body-page patterns as
well as covers/image pages; an occasional photograph does not remove repeated
prose-box treatment from the rest. Ask whether different content actually changes
focus, proportion, reading path and presentation pacing. Repair a concrete repeated
pattern when it conflicts with the user's stated visual requirements. Do not
re-render every completed page for a contact sheet or write pilot pages ahead.

Keep entry orientation visible. Reveal whole semantic units with their relevant
labels/connectors and conditions. A persistent image or diagram can anchor labels;
a retained spine can anchor branches. Do not make every word or arbitrary card a
click. Inspect the complete final view and meaningful intermediate states, reusing
host-generated states where supported. Distinguish timing/state verification from
actual PowerPoint playback. When changing animation tooling or key connector/group
structures, sample the exported file in PowerPoint where a player is available;
record the tested pages/states and any unavailable playback honestly.

Independent acquisition requests may run concurrently through the bounded media
broker; page creation remains sequential. After disconnect/resume, inspect existing
objects, saved previews, exports and receipts before redoing any work. Change only
incomplete/affected pages. Use versioned exports and frozen review/delivery bytes.
