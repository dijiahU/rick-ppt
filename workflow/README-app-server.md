# Live Codex transport

`app_server.py` replaces the closed stdin of one-shot `codex exec` with a private
stdio JSON-RPC connection. It uses only Python 3.11's standard library. The
protocol was checked against schemas generated by local `codex-cli 0.155.1` and
the [official App Server documentation](https://developers.openai.com/zh-Hans/docs/app-server).
This component has no HTTP listener and receives no website/worker credential.

## Host API

```python
from app_server import AppServer, task_configuration

config = task_configuration(
    job,
    read_roots=[plugin, python_environment, "/opt/homebrew",
                "/Applications/LibreOffice.app", "/System/Library/Fonts",
                "/Library/Fonts"],
    tool_env=bridge.environment(job),
)

with AppServer(
    cwd=job, config=config, env=bridge.environment(job),
    on_event=append_compatible_exec_jsonl,
    on_public=publish_redacted_assistant_message,
    tick=poll_lease_and_render_media_brokers,
    secrets=(worker_token, task_lease),  # redaction only; never child environment
) as server:
    started = server.start_thread(developer_instructions=task_boundaries)
    thread = started["thread"]["id"]
    turn = server.start_turn(thread, prompt, output_schema=optional_json_schema)
    journal.bind_session(thread, turn["id"])

    while (thread, turn["id"]) not in server.completed_turns:
        server.pump(.25)
        # Host website inbox polling, durable checkpointing, asset imports and
        # public progress can continue here. tick() also runs during RPC waits.
        for message in journal.pending_messages():
            receipt = server.deliver(journal, message["id"], thread,
                                     server.active_turns.get(thread))
            # Website ack uses a stable message ID, after durable runtime ack.

    result = server.result_text(thread, turn["id"])
```

The callback contract is intentionally small:

- `on_event(event)` gets compatible `thread.started`, `turn.started`,
  `turn.completed`/`turn.interrupted`/`turn.failed`, `item.started`,
  `item.completed`, plan updates and sanitized error metadata. Tool items use
  existing `command_execution`, `file_change`, `mcp_tool_call`, `web_search`,
  `agent_message`, and image-generation names. Existing trajectory/progress and
  asset-import logic can read the resulting JSONL. These host events contain
  task tool output and are **not** the browser chat feed.
- `on_public(event)` receives `assistant.message` records with `id`, `body`,
  `complete`, and `phase`, plus explicit `host.request_declined` events.
  Intermediate text is a replacement of the current partial message, not an
  append-only delta. The portal can publish/update a stable UUID derived from the
  item ID; posting each partial as a new assistant message would duplicate chat.
- `tick()` runs during `pump()` and RPC waits. It should keep leases, render and
  media brokers, trajectory sampling and queued website uploads alive. It is
  guarded against recursive tick invocation if a callback sends an RPC.

`pump(timeout)` returns new normalized events and also calls the callbacks.
Choose one ingestion route to avoid duplicate recording. `wait_turn(thread, turn,
timeout=...)` is convenient for tests; production may instead keep its explicit
phase loop. `result_text()` returns the completed final-answer item, falling back
to the last completed assistant item when the provider did not label its phase.
`completed_turns` contains metadata receipts, not raw turn-item histories.

## Delivery, races and recovery

Both `turn/start` and `turn/steer` send `clientUserMessageId`; it round-trips into
the persisted `userMessage.clientId` in this CLI version. `steer()` requires the
trusted active turn ID as `expectedTurnId`. `deliver(journal, message_id,
thread_id, active_turn_id=None)` records `delivering` before writing the RPC and
records acknowledgement only after a successful response.

A timeout, broken pipe or internal error remains ambiguous. `reconcile_delivery`
pages `thread/items/list` looking for the exact client message ID. A found ID
confirms acknowledgement without resending. An absent ID remains uncertain;
missing/incomplete history is not proof of non-delivery.

A definitive JSON-RPC invalid-params rejection permits an explicit retry. This
binary additionally reports an idle/completed-turn steering race as error
`-32600` with the exact message `no active turn to steer`; that specific pair was
verified against the real binary and is also classified as non-acceptance. Other
`-32600` and internal errors are conservatively uncertain. After a proven race,
the host resynchronizes the current turn and calls `deliver()` once more using
`turn/start` if idle or the new expected turn if active. The transport never
blindly starts a second turn after a lost response.

`interrupt(thread_id, turn_id)` waits for the RPC acknowledgement; then wait for
`turn/completed` with `status="interrupted"`. An interrupted turn is not reported
as a completed phase. A new server process can `resume_thread(thread_id)` with
the current task directory and the same confinement overrides. The restored
workspace can be a new journal attempt directory. If the thread cannot be
resumed, the host starts a fresh context from the verified files/brief/inbox;
it does not replay archived shell commands.

`start_thread()` and `resume_thread()` return trusted method receipts. Resume
does not need to emit a new `thread.started` event, so record its returned ID
directly. Output-schema constraints are sent as `turn/start.outputSchema`;
`turn/steer` cannot change that constraint in the middle of the turn.

## Confinement and configuration

The helper uses the existing runner's named `pptx_job` permission profile:
filesystem default deny, a minimal OS read set, task-directory writes, explicit
runtime/font read roots, temp-directory exclusion and shell network disabled.
It does not use plain workspace-write as a substitute for read isolation. The
legacy response describes the profile as `workspaceWrite`; actual canary tests,
not that label, establish read/write/network confinement.

The environment allowlist excludes host queue/API tokens and HOME/CODEX_HOME
overrides. It permits task-local `PPTX_SOFFICE` and `PPTX_INTERACTIVE_PROXY`
helpers. Proxy variables may be present in the app-server's network environment
but are excluded from the tools' explicit environment. Local Codex authentication
continues through the installed CLI's existing auth boundary. No auth file is
copied into a task or public report.

Unlike `codex exec`, app-server 0.155.1 does **not** support the exec-only
`--ignore-user-config` or `--ignore-rules` options. The transport therefore applies
explicit permission/environment overrides; disables apps, plugins, hooks,
browser/computer controls, memories, shell snapshots and multi-agent features;
and sets project document ingestion to zero. It reads only configured MCP server
names from known TOML configuration layers, passes a separate `enabled=false`
override for every name, and repeats that disablement from effective configuration
before starting/resuming a thread. Configuration values are never logged.
An empty MCP map is deliberately not used: layer merging or removing transport
fields can produce incomplete server definitions. Unsupported server-name syntax
fails closed instead of leaving a configured server enabled.

Approval policy is `never`; any unexpected command/file approval, permission
request or MCP elicitation is explicitly declined. Optional user-input requests
receive an empty answer so the unattended task does not wait on a sleeping user.
Dynamic host tools and auth-refresh callbacks are not implemented or filled with
host credentials. The worker may explain a real unavailable capability through
normal task status, but cannot expand its own permissions.

## Data handling and bounds

The initialize handshake opts out of reasoning notifications. Reasoning items
are also filtered at ingestion; they are not normalized, published or retained
in completion receipts. Public assistant text redacts provided secrets, common
credential forms and private absolute paths. Streaming retains a trailing buffer
and incomplete word so split credential fragments are not exposed early.
Task-scoped tool output remains in the existing private trajectory pipeline,
whose own redaction still applies.

Protocol lines and assistant items are bounded to 8 MiB by default. Outbound
requests are bounded, stderr keeps only a 16 KiB redacted diagnostic tail, and
readers use a bounded queue. A malformed/oversized/incomplete frame fails the
connection; a late response cannot satisfy a newer request ID. Callbacks run in
the host's calling thread while background readers only frame/queue bytes.
The transport closes only its own new app-server process group.

Token usage uses host-reported per-turn notifications, deduplicates repeated
totals and adds deltas after the first reported model response. A resumed
thread's lifetime token total is not incorrectly charged to its first resumed
turn. If no usage receipt was exposed, the field remains `None` rather than an
invented zero; integration should record the visibility gap.

## Verification

```sh
python3.11 -m unittest discover -s workflow -p 'test_app_server.py' -v
python3.11 workflow/test_app_server.py --live --out /new/private/path/proof.json
```

The default suite has 20 tests covering handshake/config overrides, normalization,
active and idle delivery, definitive turn races, lost responses, reconciliation,
interruption/resume, exact schema fields, usage, reasoning exclusion, public
redaction, environment isolation, denied host callbacks and malformed frames.

The real local smoke **passed** on 2026-09-20 Asia/Shanghai with
`codex-cli 0.155.1` (2026-09-19 20:13:58–20:14:47 UTC). Its non-secret proof records:

- outside-task read denied, outside-task write denied and shell network denied;
- a correction sent while a tool was active stayed in the same turn and wrote
  the requested `STEER_RECEIVED` artifact;
- the supplied client message ID appeared in persisted thread items;
- an active tool turn was interrupted, the app-server process restarted, and
  the identical thread resumed and recalled the earlier marker without tools;
- approval policy remained `never`, four assistant messages reached the public
  projection, and reasoning was excluded.

The proof file is generated outside source control and contains booleans, timing
and CLI version, not full conversation/session contents or credentials. The smoke
creates and retains its own isolated artifacts; it never touches live queue jobs.
Website/lease/broker integration is a separate acceptance gate.
