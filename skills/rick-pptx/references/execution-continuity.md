# Work from current files and concrete outputs

Use the current task directory and task-relative paths. When provided by the
host, `tool-quickstart.md` contains the real interpreter and ready command
arguments; `tool-manifest.json` contains the selected parts directory and exact
interfaces. Otherwise use the installed skill's actual helpers and environment.
After selecting and
unpacking the appropriate source once, refresh tool preparation with that returned
workspace. Reuse it. Older absolute paths in a resumed conversation are historical.

For chosen native objects, prefer `native_page_batch` and
`references/native-batch.md` when actually provided. Otherwise use the available
native canvas/OOXML helpers. Use the actual interface for operations you need.
Advanced native helpers and direct OOXML remain available.
Read implementation source only for a specific interface gap/error; do not spend
a preparation phase discovering the tool directory or building another framework.
Write long native batches/scripts in usable pieces, applying them to the current
page, rather than depending on one very large generated command arriving intact.

Research produces supported source notes and an ordered outline/decision handoff.
Record verified observations and open questions while investigating; do not wait
to identify every pixel/color before recording the main structure. Source matching
still preserves all required labels, qualifiers, relationships and token states.

The continuing author first implements the main relationship on the current page
in normal page order, then checks its actual render and refines detail. A partial
composition is revisable, not an approved template for the remaining deck. Source
precision, creative exploration and factual investigation remain available when
they resolve a concrete issue. There is no reference quota, layout template or new
review gate. File listing, repeated crops, color sampling, status messages and API
heartbeats alone do not establish an authored page or a completed investigation.

When supported, the host may request a concrete saved output after tool actions without
phase-output changes. If that remains unsuccessful, it may preserve files and
start one new context for the same role/model, using the current handoff. This is
execution recovery, not a new author in parallel. It does not relax scope, facts,
native editability, animation, source constraints or independent review. Missing
mandatory material must be reported honestly, never fabricated to show progress.

For a complete deck or a finished repair, use manifest save_candidate when available.
It combines the existing native export/render, authored check and atomic delivery
declaration. Keep a complete checkpoint after a main useful correction and refresh
it after further completed changes. Retained working edits alone cannot cross the
host's explicit-candidate boundary. Preserve older exports; no independent review
or target-player certification is implied by saving.
