# Native PPT visual revision workbench

Website v33 is published at https://rickppt.aaarickmorty.chatgpt.site. The task workspace now opens a large native-render canvas, slide thumbnails and a contextual revision sidebar. It supports object/region/whole-slide comments, text replacement requests, PNG/JPG replacement via existing private staged uploads, batched submission, locally retained unsent notes, safe retries, previous snapshot selection and before/after comparison. Undo currently removes unsent changes; this release does not implement arbitrary object dragging or in-browser animation playback.

Each immutable canvas manifest carries a PPTX SHA-256, a public version UUID (not the worker lease), exact slide-part/native-object IDs, normalized slide-space bounds, text and per-image SHA-256. Parent group transforms and rotation are composed before hit testing. Unsupported inherited geometry remains available for region comments; formulas/fields are not advertised as editable plain text.

POST visual-edits checks owner/CSRF, actual object/original text and the current delivered hash. It preserves the delivered result while atomically saving a revision and resuming the same task without a new quota charge. Each request receives an immutable baseline copy; the host downloads it through a lease-fenced endpoint, verifies its SHA and standalone-PPT policy, and publishes it under visual-inputs. Internal baseline files do not count against user attachment limits. The model receives scoped instructions with exact page/region/object identity. Simple replacements are still applied through the production author; this version does not claim zero-model-latency editing. Source-preserving verified visual revisions can reuse planning after the existing validator, rather than repeating subject research. Native export and the existing checks still run.

The worker snapshot publisher reuses export-matched actual PNGs and native object geometry; no extra render is introduced just to initialize the canvas. Preview publication failures defer only the editing snapshot, not a valid PPT delivery. Immutable manifests and previews are private to owner/admin readers. As of Site v34, administrators can explicitly enable administrator editing on other users' tasks. Server-side role and opt-in checks are required; edits preserve the task owner and record the submitting administrator. Conversation is the default visible sidebar tab, and structured visual requests display as human-readable chat summaries. Snapshots support future deliveries; the 25-page GPTROGUE case was backfilled without changing its completed status, PPT bytes or quota.

Validation: TypeScript, production Vinext build, actual route tests with transactional SQLite/R2 adapters, owner/admin/CSRF checks, stale version and conflicting retries, retained downloads, picture upload/source transport, real 25-page manifest, native group/rotation transforms and baseline checksum rejection. Existing conversation, attachment preview, delivery, decision-routing and HTTP recovery tests passed. No browser was connected to the supported runtime, so interactive browser/visual QA was unavailable; no claim of actual UI or WPS playback certification.
