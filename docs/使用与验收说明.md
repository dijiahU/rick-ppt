# 新工作流的使用与验收

网站仍使用原来的账号和任务列表。制作中的任务页面增加了对话区：选择
“修改要求”会让正在工作的 Codex 接收并处理新要求；选择“普通聊天”可以
询问进度或讨论内容。消息可以附带 PDF、PPTX、DOCX、TXT、MD、CSV、PNG
或 JPG，每条最多 3 个文件，单个 10 MB、合计 20 MB。

消息状态分别表示已经发送、已经接收、已经落实。“已经接收”不等于修改
已经完成；最终交付还要经过当前版本的验证与审核。重新打开页面会接着
显示对话和进度。已有可用检查点的任务停止后，可以在同一任务中继续，
保留之前的文件和版本，也不会重新占用一次任务准入额度。

## 在这台 Mac 上打开交互内容

1. 下载并完整解压交互 ZIP，保留目录结构。
2. 运行解压目录中的 `scripts/start.command`，再打开 `presentation.pptx`。
3. 查看浏览器版时，使用包内 `README.txt` 给出的预览链接。
4. 结束后运行同目录的 `scripts/stop.command`。切换到另一个单独的包时，
   先停止当前包，因为两者默认使用同一个本机端口。

本机已经准备好 Python 依赖、localhost 开发证书和 PowerPoint 的 XML
加载项配置。启动脚本会核对文件哈希；它只管理自身的运行时进程。PowerPoint
使用 manifest 声明的 `https://localhost:41973`，浏览器专用的 HTTP 调试地址
不能代替这个 Office 地址。换到另一台电脑时，按包内 README 配置环境、
证书和加载项。

课堂上的滑块值、临时编辑的代码和上传输入属于当前播放会话，不会自动
写回 PPTX。制作任务的断点恢复由工作流日志负责，这与听众播放时的临时
状态是两件不同的事。
