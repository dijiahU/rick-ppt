# Public task review results

The task page now has a persistent content/visual review status strip and a Review results tab. It shows first reading, content/source validation and visual design reports; required changes and suggestions have separate counts and styles. Findings include page numbers, observed problem, audience impact and concrete recommendation. Coverage, recorded time and limitations remain visible, including missing Windows WPS/PowerPoint playback verification. Report text is escaped, not inserted as HTML.

`GET /api/jobs/:id/reviews?after=N` authorizes the task owner or administrator before reading any execution storage. It reads the existing bounded trace cursor internally and projects only structured reviewer reports. No commands, tool output, private reasoning, transport details or lease are returned. It does not mutate a job, consume quota or start a review. The client drains history in bounded pages, polls while work continues, retries failed reads and resets history when the attempt changes.

Existing app-server reviewer outputs can be recovered from structured final Assistant update records scoped to content-first/content-evidence/visual stages. These historical reports did not record an artifact hash in the trace and are explicitly labeled Version not recorded. They are historical findings, not assertions that the current draft passed.

Future workflow executions additionally publish validated public review envelopes through the existing trace transport after the actual review returns. These contain the exact frozen artifact SHA-256, input revision, round and role. Public excerpts remain below the trace detail's UTF-16 bound, retain total required/suggestion counts when abbreviated and leave complete original reports in the local archive. This adds no model call or review gate. A visual static pass does not become a claim of tested playback.
