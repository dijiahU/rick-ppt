# Rick 的交互演示使用指南

你可以在网站制作过程中继续提问、补充资料和提出修改；任务中断后，有可用恢复点时可以继续原任务。交付时，PPTX 用于查看和编辑幻灯片，交互演示 ZIP 用于运行其中的代码、控件和动画。本指南说明实际操作，不代表某个具体任务已经交付。

## 制作中提问、修改和上传

登录创建任务时使用的账号，打开自己的任务详情页，在 **“和 Codex 一起制作”** 中发送消息。任务页的 **“设计与进度”**、**“活动记录”**、**“来源链接”** 和 **“页面预览”** 可以查看当前工作；预览仍可能随修改更新。

先选消息类型：

| 选项 | 什么时候用 | 示例 |
| --- | --- | --- |
| **修改要求** | 希望改变内容、页面、代码、动画或采用新的参考文件。默认选中此项。 | “第 4 页增加一个可修改参数的例子，保留原来的解释，并说明无效输入。” |
| **普通聊天** | 询问原因、进度或概念，只需要回答。 | “这一步为什么需要归一化？” |

普通聊天按问答处理，不自动修改演示文件。要落实修改，请使用 **“修改要求”**；聊天中的回答也不能当作页面已经改好的证明。

输入后点击 **“发送”**，或按 **⌘ Enter**；Windows 键盘也支持 **Ctrl Enter**。单条消息最多 8000 字，以输入框实际限制为准。消息会保存在同一个任务里；对话区显示最近 200 条。

点击 **“添加附件”**，也可以把文件拖入消息输入区，或粘贴剪贴板中的图片文件。支持：

```text
pdf、pptx、docx、txt、md、csv、png、jpg、jpeg
```

每条消息最多 3 个文件，每个不超过 10 MB，合计不超过 20 MB。选中文件后还要点击 **“发送”**，附件才随消息上传；只有附件、没有文字也可以发送。待发送列表中的 **×** 可移除本次选中的文件，不会删除已经发送的资料。其他格式目前没有网站上传入口。

需要作者采用附件中的内容时，选“修改要求”，并写明“参考哪些部分、需要改哪里”。选“普通聊天”上传的文件用于这次问答，不自动变成制作要求。

## 看懂“发送、收到、应用”

| 显示文字 | 表示什么 |
| --- | --- |
| **正在发送 …%** | 正在上传这条消息及附件。进度到 100% 仍需等待服务器确认。 |
| **已保存** | 网站已经保存；执行端可能还在排队、离线或等待接收。 |
| **Codex 已收到** | 本轮制作已经接收到消息；修改可能还在进行。 |
| **已应用** | 对修改要求，相关产物已完成验证并确认包含该要求；对普通聊天，表示相应回答已完成。 |

看到“已应用”后，再结合更新后的页面预览或新版本检查实际效果。这一状态不表示已经在你的 PowerPoint 里完成播放验证。

页面通常每 3 秒同步一次。遇到 **“连接中断，正在重连…”**，先等自动重连；任务页也有 **“立即刷新”**。若提示 **“发送未确认，可安全重试”**，在当前页面保持原消息和附件不变，再点“发送”。修改文字、类型或附件会开始一条新的发送。尚未发送的草稿和选中文件没有成为保存的消息，刷新前应留意这一点。

## 失败后从断点继续

回到原任务详情页查看状态。出现 **“恢复点已保存”**，说明执行端曾保存制作进度；任务已完成或失败，并且恢复点可用时，会出现 **“从断点继续”**。

1. 如有新要求，先在原任务中发送“修改要求”或补充附件。
2. 点击 **“从断点继续”**。原任务会重新排队，接着处理已有轨迹和新消息。
3. 继续观察任务进度、消息状态和新预览。此前已交付的版本仍可在“历史版本”中下载。

恢复从最近有效的保存点开始，最后一小段未保存的工作可能需要重做；已有内容也可能因新要求而重新检查。它不承诺回到中断瞬间的每一步操作。

正在排队或制作时，不需要点恢复。看到 **“执行端超过两分钟未更新”** 也不等于任务已经失败，可以先点“立即刷新”核对状态。没有恢复按钮，或提示 **“当前没有可用恢复点、任务已变化或队列已满”** 时，先刷新；仍不可用就保留原任务链接和记录，交由执行端排查，不必删除任务或资料。

关闭网站页面本身不会取消已经提交的制作任务。稍后用同一个账号回到原任务即可查看进度。

## 下载 PPTX 和交互演示包

任务完成且成品可用时，详情页提供 **“下载 PPTX”**。对话区下方的 **“历史版本”** 按时间列出已有交付：

- **PPTX ↓**：下载该版本的演示文稿。
- **交互演示包 ↓**：下载该版本的 ZIP；只有实际生成过交互包的版本才显示这个链接。

要保留完整交互，请从同一个历史版本下载两种文件。没有“交互演示包”链接时，不能仅凭 PPTX 或页面截图判断交互资源已经交付。

ZIP 解压后应能看到 `presentation.pptx`、`README.txt`、`scripts/`、`deck/`、`runtime/` 和 `manifests/` 等内容。保留整个目录。单独的 PPTX 保留原生文字、图形及交互区域的静态预览；运行交互还需要同版本的演示包和本地服务。

需要编辑原生 PPTX 时，**另存一份到包外**。不要把修改后的文件覆盖回交互包，也不要在包内添加 Python 环境、笔记或改动校验文件；启动程序会检查整包完整性。网页“页面预览”是页面图像，不能用来测试按钮或代码执行。

## 在 Mac 上打开交互包

以下命令都从**解压后包含 `presentation.pptx` 和 `scripts/` 的目录**运行。它们使用包内实际提供的启动、停止和校验程序，不需要启动网站执行端或 Docker。

### 第一次准备 Python

需要 Python 3.11 或更新版本。下面以已安装的 `python3.11` 为例，把环境放在交互包的同级目录；已有按此方式准备的环境可以复用，不必重新创建。如果同级已有同名目录且用途不明，另选一个新名字，并相应替换后续命令。

```sh
python3.11 -m venv ../pptx-viewer-env
../pptx-viewer-env/bin/python -m pip install -r scripts/requirements.txt
../pptx-viewer-env/bin/python scripts/bundle_control.py verify
```

校验成功会返回 `"ok": true`。如果提示文件缺失、哈希不符或文件清单变化，保留当前目录，重新下载或解压到一个新目录核对，不要编辑校验清单让错误消失。

### 先在独立浏览器中查看

这个方式使用本地 HTTP，不需要 Office 证书或侧载加载项：

```sh
PPTX_PYTHON=../pptx-viewer-env/bin/python sh scripts/start.command --http --port 41975
../pptx-viewer-env/bin/python scripts/bundle_control.py status
```

启动成功会返回 `"running": true` 和服务 `url`。在包的 `README.txt` 中找到 **Standalone preview** 的完整链接，把开头的 `https://localhost:41973` 换成启动返回的地址（此例为 `http://127.0.0.1:41975`），保留后面的页面与场景参数，然后在浏览器打开。

停止这个包的服务：

```sh
PPTX_PYTHON=../pptx-viewer-env/bin/python sh scripts/stop.command
```

关闭浏览器窗口不会自动停止后台服务。启动和停止应针对同一个解压目录；重复启动已在运行的同一包，会返回现有实例。停止脚本只停止该包管理的服务，不会按进程名称结束其他程序。

### 在 PowerPoint 中打开

PowerPoint 的交互区域使用 **`https://localhost:41973`**。需要本机已信任的 localhost 证书，以及包中 `manifests/manifest.addin.xml` 对应的加载项；上面的 HTTP 浏览器模式不能直接代替这些准备。

如果这台 Mac 还没有配置证书，在**已经安装依赖并构建好插件的 `pptx-agent` 目录**运行现有命令：

```sh
.venv/bin/pptx interactive cert status
.venv/bin/pptx interactive cert install
.venv/bin/pptx interactive doctor
```

本项目的证书安装命令保留已有证书文件；遇到不完整的证书集合会报错并保留现场。首次安装所需环境见[插件说明](../pptx-agent/README.md)。只有演示包、尚未配置插件环境时，可以先用独立浏览器模式。

首次侧载 XML 加载项时，按 [Microsoft 的 Mac 操作说明](https://learn.microsoft.com/en-us/office/dev/add-ins/testing/sideload-an-office-add-in-on-mac)，通过 Finder 前往 PowerPoint 的 `wef` 目录：

```text
~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/wef
```

把包中的 XML manifest 放入该目录，再重启 PowerPoint；不要覆盖不明用途的已有文件。已经安装过同一加载项时，先核对已有配置，避免重复改动。以上是官方支持的准备方式，不代表本项目已经完成桌面播放验收。

回到**演示包目录**，先停止该包之前的 HTTP 服务，再以默认 HTTPS 启动：

```sh
PPTX_PYTHON=../pptx-viewer-env/bin/python sh scripts/stop.command
PPTX_PYTHON=../pptx-viewer-env/bin/python sh scripts/start.command
../pptx-viewer-env/bin/python scripts/bundle_control.py status
```

浏览器访问 `https://localhost:41973/api/health` 应能正常打开，再打开 `presentation.pptx`。讲解期间保留服务运行；结束后仍用同一条 `stop.command` 停止。默认端口被其他演示包占用时，先从那个包的目录停止它，不要随意换端口后期待 PowerPoint 自动找到服务。

**当前证据边界：**Mac 的包启动/停止、独立浏览器交互和静态渲染已有实际验证；桌面 PowerPoint 内的加载、放映和保存重开仍需按照[实测清单](../pptx-agent/docs/manual-powerpoint-verification.md)逐项确认。看到健康接口、静态画面或浏览器动画正常，不等于桌面放映已通过。

## 使用代码编辑器

有代码实验的页面会显示真实编辑器，顶部有以下英文按钮；无障碍名称分别为 Run code、Stop code、Reset code。

| 按钮 | 操作 |
| --- | --- |
| **Run** | 运行编辑器里当前的代码。观察下方输出、错误信息，以及该页面与结果联动的图示。 |
| **Stop** | 终止这次正在运行的代码。它不负责恢复初始代码。 |
| **Reset** | 停止当前运行，恢复该编辑器的原始代码并清空输出。需要重新计算默认结果时，再点 Run。 |

首次运行 Python 可能需要等待本地运行环境加载。每次 Run 都从新的执行环境开始，不会延续上一次运行的变量。这里支持已准备好的教学代码和本地依赖，不是任意联网安装库的终端。

可以直接改数字、按键输入或粘贴代码；粘贴完整 Python 程序时使用正常的 **⌘ V**，并留意缩进。报错后查看输出，修正后重跑，或用 Reset 回到原始代码。教学行高亮用于配合讲解，不是可以停住程序的调试断点。

代码区的 Reset 针对这个编辑器；整页其他滑块、动画或选择器的复位范围，以页面提供的操作为准。不要把“停止代码运行”与网站制作任务的“从断点继续”混为一件事。

## 哪些状态会保留

网站中已经发送的消息、附件、制作恢复点和已交付版本属于制作记录。课堂里临时改动的滑块值、代码和输入属于当前演示会话，**不会自动写入 PPTX，也不保证关闭后重开仍保留**。需要永久修改课程内容时，回到网站提交“修改要求”，取得新的交付版本；需要保留临时代码时，先自行复制保存。
